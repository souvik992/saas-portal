# posinext.com website

Plain static HTML in `public/`, generated by `src/build.py`. The only JavaScript is the small inline Book a Demo script, and each page carries its CSS
inline (one request to render). They are built to load on slow 2G connections: about 7–12 KB gzipped per page, WebP images
sized for the screen (`srcset`) and lazy-loaded below the fold, and self-hosted fonts with `font-display: optional`, so
text never waits for a font.

The design is the original Lovable site's (gallery-of-stories.lovable.app), rebuilt by hand in `src/site.css`.

## Change the site

Edit the sources, then run the build (Python 3 with Pillow and fontTools):

```bash
pip install pillow fonttools brotli   # once
python site/src/build.py
```

| File | What it holds |
|---|---|
| `src/kit.py` | Reusable parts: page shell (head, SEO meta, JSON-LD), header, footer, buttons, cards, FAQ, CTA band, breadcrumbs, icons, images |
| `src/products.py` | The 9 products: home-page blocks and each product page (features, steps, FAQ) |
| `src/build.py` | Home page, product pages, image conversion |
| `src/pages.py` | Features, pricing, changelog, compare, about, careers, contact, book a demo, docs, help, status, privacy, terms, security; 404, sitemap, robots, llms.txt, llms-full.txt, ard.json |
| `src/posts.py` | Blog posts |
| `src/site.css` | All styles (minified and inlined by the build) |
| `src/images/` | Original images; the build makes `public/img/<name>-480/800/1200.webp` |

Add a page: call `simple(...)` in `src/pages.py` (or add a product to `products.py`), and add it to `FOOTER` in `kit.py`
if it belongs there. The sitemap and llms files are regenerated from what was built.

## Put it on the server

On the PosiNext Cloud server (it runs Caddy), after DNS for `posinext.com` and `www.posinext.com` points at it:

```bash
curl -fsSL https://raw.githubusercontent.com/souvik992/saas-portal/main/site/deploy.sh | sudo bash
```

The script builds the site on the server (`src/build.py` in a private Python venv), so `/admin/` and CMS posts are always
included, and installs `posinext-site-update.timer`: every 10 minutes it rebuilds if `main` has a new commit (e.g. a post
saved in `/admin/`) or the India date changed (scheduled posts). Force a rebuild with `sudo posinext-site-update --force`.
`www.posinext.com` redirects to `posinext.com`.
Unknown addresses return a real 404 with `404.html`. The script only writes `/etc/caddy/posinext-site.caddy` and undoes
everything if Caddy does not accept the result.

## Notes

- **Sign in** opens `https://portal.posinext.com/login`; **Start your free trial** opens `https://portal.posinext.com/register`.
- **Book a Demo**: every Book a Demo link opens the demo form in a dialog (the page's only script, `DEMO_JS` in
  `kit.py`); without JavaScript the link goes to `/book-a-demo/`, which shows the same form. It posts to
  `https://portal.posinext.com/v1/demo-requests` (PosiNext Cloud), which saves the request and emails it to
  `HUB_DEMO_REQUEST_TO` on the server. The only email address shown anywhere is `support@posinext.com`.
- Prices on `/pricing/` match the portal's plans (`cloud/saas-web/src/plans.ts`); change both together.
- After a deploy, submit `https://posinext.com/sitemap.xml` in Google Search Console and Bing Webmaster Tools.


## Blog CMS (serverless)

The CMS admin interface is built from `site/src/admin.html` and is served at `/admin/`. It uses the GitHub Contents API directly:
- Enter admin label `souvik` and a fine-grained GitHub personal access token for this repository.
- Scope the token to `souvik992/saas-portal` only, with **Contents: Read and write**. The token remains in the browser tab's memory and is not saved to browser storage or committed.
- Create and edit CMS posts, save drafts, publish immediately, or schedule a future date for the daily 9:00 AM India-time build.
- Posts are JSON files in `content/posts/` at the repository root. Drafts are omitted from the public site; published posts and scheduled posts whose date has arrived are rendered into static HTML.
- Article body markup is sanitized by `site/src/cms.py` before rendering.
- The daily GitHub Actions workflow builds and deploys the static website. No app server, database, production Caddy host or VPS is required for the CMS or deployment.

### Enable serverless website hosting

In repository **Settings → Pages**, set the publishing source to **GitHub Actions**. The workflow `.github/workflows/site-pages.yml` builds the static site and deploys `site/public` using GitHub Pages. GitHub's workflow and domain setup guides:
- [Configure a GitHub Pages publishing source](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site)
- [Configure a custom domain and DNS](https://docs.github.com/en/pages/configuring-a-custom-domain-for-your-github-pages-site/managing-a-custom-domain-for-your-github-pages-site)

Complete the custom-domain cutover in this order:
1. In repository **Settings → Pages**, keep **GitHub Actions** as the publishing source. Under **Custom domain**, enter `posinext.com` and click **Save**. GitHub's custom-domain field must be configured even when using a custom Actions workflow.
2. At the DNS provider for `posinext.com`, point the apex `@` to all four GitHub Pages A-record targets: `185.199.108.153`, `185.199.109.153`, `185.199.110.153`, and `185.199.111.153`. For `www`, create a CNAME pointing to `souvik992.github.io`.
3. Remove only conflicting web-host A/AAAA/CNAME records for `@` and `www`; do not delete mail (MX), verification or other unrelated TXT records. GitHub recommends adding the custom domain in Pages before changing DNS.
4. After DNS validates, enable **Enforce HTTPS** in Pages settings. DNS updates may take up to 24 hours.

Until these GitHub Pages and DNS settings are complete, the old production host remains in control of `posinext.com`, so a successful Actions run alone does not prove that the custom domain serves the new admin page.
